# vault-lint

Verify the vault. Three tiers of checks. Report-only with ONE scoped write exception: Check 26 regenerates `patterns/language-glossary-master.md` (DERIVED, never authored). Every other surface is untouched. The user decides what to fix.

vault-lint catches what vault-sync and vault-restructure leave behind. Lint is the verify phase, not the build phase.

---

## Step 0: Detect Mode and Scope

Parse flags from the invocation:
- `--fast` → run Tier 1 only (skip Tier 2)
- `--semantic` → run Tier 1 + Tier 2 + Tier 3
- (no flags) → run Tier 1 + Tier 2

Check whether the current working directory is a vault root:

```bash
ls CLAUDE.md wiki/index.md 2>/dev/null
```

If neither file exists: report "not a vault root — run /vault-toolkit:vault-restructure or /vault-toolkit:vault-sync first" and stop.

If CLAUDE.md line 1 contains `[RESTRUCTURE STUB`: report "vault has an unfinished restructure stub — run /vault-toolkit:vault-sync to complete CLAUDE.md before linting" and stop.

Lazy-load `references/checks.md` here for the full check definitions.

## Tier 1: Structural Checks (always run)

Tier 1 reads only:
- CLAUDE.md
- wiki/index.md
- wiki/restructure-manifest.md (if present)
- wiki/vault-index.md (if present)
- File system listing via `find . -maxdepth 3 -name "*.md"`
- File mtimes

Tier 1 does NOT read individual wiki page bodies. Cheap. Fast.

Run all 8 Tier 1 checks (full definitions in `references/checks.md`):

1. **Required file presence** — verify CLAUDE.md, wiki/hot.md, wiki/index.md, wiki/log.md, wiki/session-handoff.md, wiki/reasoning.md (last is conditional on `.vault-config.yaml` `reasoning_log: enabled`)
2. **CLAUDE.md line count** — flag if over 80 lines
3. **Index drift** — ghost entries (in index, not on disk), unlisted files (on disk, not in index)
4. **Invalid frontmatter syntax** — every wiki/*.md must open with a valid `---` YAML block. Exempt coordination files: `wiki/hot.md`, `wiki/index.md`, `wiki/log.md` (session-state templates intentionally omit frontmatter). Also exempt auto-generated vault coordination files: `wiki/vault-index.md` (per-page catalog generated by vault-restructure, documents itself in opening paragraph) and `wiki/restructure-manifest.md` (generator-written YAML only). `wiki/session-handoff.md` and `wiki/reasoning.md` are NOT exempt; their templates include frontmatter.
5. **Duplicate page titles** — two pages with identical `title:` frontmatter cause LLM retrieval ambiguity
6. **Manifest / vault-index hash drift** — files with mtime newer than vault-index `last_processed`
7. **hot.md staleness** — hot.md mtime vs max mtime of any wiki page modified since. Also flag if hot.md exceeds 30 lines (Section 9.2.2 cap: trim by compressing Active Decisions to one line each and moving older items to session-handoff.md)
8. **Broken internal links** — parse `[text](path)` and `[[wikilinks]]`, resolve against file tree, exclude code blocks

Record each check as ✅ pass, ⚠️ warning, or ❌ fail.

## Tier 2: Quality Checks (default; skip with --fast)

Tier 2 reads page bodies but ONLY for changed files + their link-neighborhood (one hop in either direction). Full Tier 2 across the whole vault is reserved for explicit weekly runs (the user can pass `--full` to force it).

**Scope determination for Tier 2:**
- "Changed files" = files with mtime newer than vault-index `last_processed`. If vault-index doesn't exist: use files modified in the last 7 days.
- "Link neighborhood" = pages that link TO or are linked FROM a changed file (one hop)
- This caps token cost. Codex estimates: 18k-30k for small vaults, 45k-75k for medium, 90k-150k for large.

Run all 16 Tier 2 checks (full definitions in `references/checks.md`):

9. **Orphan pages** — zero inbound links AND not in index.md (advisory: intentional quiet pages exist)
10. **Isolated pages** — no outbound OR inbound links at all
11. **Oversized pages** — >800 words excluding frontmatter and code blocks (split candidate)
12. **Stale frontmatter dates** — `updated:` field >90 days old. Exempt: pages with `status: evergreen` (intentionally stable) or `status: archived` (frozen by design). Only flag `status: draft` and `status: active` pages.
13. **Duplicate headings within a page** — two or more identical heading text in same file
14. **Missing required frontmatter fields** — `type`, `title`, `description` required on wiki knowledge pages. Exempt the same coordination files as Check 4: `wiki/hot.md`, `wiki/index.md`, `wiki/log.md`, `wiki/vault-index.md`, `wiki/restructure-manifest.md`.
15. **reasoning.md / log.md near thresholds** — approaching 400 / 150 lines (remind to run vault-sync for archival)
16. **hot.md / session-handoff.md contradiction** — if "current state" and "running state" disagree
17. **Low-signal pages** — frontmatter + title present, fewer than 50 words of body (stub never completed)
18. **Summary drift** — `description:` field no longer matches the page body's first heading or first paragraph
19. **Dangling index sections** — wiki/index.md section heading with no entries, or entries pointing to non-existent paths
22. **Unlinked draft pages** — pages with `status: draft` AND `maturity` other than `placeholder` that have zero inbound wikilinks. These are files, not knowledge. Report them with the suggestion: add at least one inbound link or set `status: active` once linked. Exempt: pages with `maturity: placeholder` — Bootstrap-seeded stubs are not yet knowledge and will pass this check until populated. (Complement to Check 10 — Check 10 flags zero links in either direction; this check specifically targets the unlinked-draft state defined by the born-linked rule, Section 9.1.2.)
23. **Re-ingestion sweep candidates** — scan `raw/archive/` for files whose archive date predates the most recent wiki page creation date. If any exist, flag: "N archived raw files predate new wiki pages — a re-ingestion sweep may surface new connections. Run /vault-toolkit:vault-sync with the archived files as source." Count only; do not read archived file bodies.
25. **Stale active/draft pages** — wiki pages with `status: draft` or `status: active` AND `updated:` > 90 days. These are pages that are neither frozen (evergreen/archived) nor recently maintained. Report with: page name, current status, days since update, suggested action (complete + promote, or archive). This is the refined stale-page gate; Check 12 handles frontmatter data quality; Check 25 handles page lifecycle action.

26. **Cross-project language conflicts (derived glossary-master)** — runs every lint pass. Walks every project row in `~/Anmols Files/CLAUDE/patterns/language-index.md`, reads each `wiki/language.md`, regenerates `~/Anmols Files/CLAUDE/patterns/language-glossary-master.md` (DERIVED — explicit exception to Hard Rule 1, scoped to this one file), then flags cross-project conflicts.

    **Missing index.md:** if `patterns/language-index.md` is absent, emit `⚠️ Check 26 skipped: patterns/language-index.md not found. Run /vault-toolkit:vault-restructure on a project to seed the registry.` and skip the check. Never silently no-op.

    **Stale registry rows:** for each index row, resolve its path. If the file is missing, emit `⚠️ Stale registry row: <project> → <path> not found. Remove from patterns/language-index.md or restore the file.` and exclude that project from both generation and conflict detection.

    **Per-term parser contract:** canonical = H3 heading text after `### ` (trimmed); definition = text after `**Definition**:` on its line (one line, no continuation); status = value after `**Status**:` if present, defaults to `active`; term block boundary = next `### ` or EOF. SKIP terms with Status `AMBIGUOUS` (with or without ` — decision pending` suffix) — deferred decisions do not enter the master and are not eligible for conflict detection. Malformed blocks (missing Definition, malformed H3, duplicate canonical in one project) are logged as `⚠️ Malformed term in <project> language.md: <reason> (heading line ~N)` and skipped.

    **Generation logic:** Build one table per canonical term, grouped alphabetically. For each canonical, emit:
    ```
    ### <Canonical Term>
    | Project | Definition |
    |---|---|
    | <projectA> | <definition from projectA> |
    | <projectB> | <definition from projectB> |
    ```
    Frontmatter for the generated file:
    ```yaml
    ---
    type: derived-glossary-master
    generated_by: vault-lint
    generated: <YYYY-MM-DD HH:MM>
    source_hash: <sha256 of concatenated input language.md bodies, sorted by project name>
    body_hash: <sha256 of the rendered body below this frontmatter, excluding the trailing newline>
    ---

    > AUTO-GENERATED by vault-lint. Do not edit. Edit per-project wiki/language.md and re-run vault-lint.
    ```
    `source_hash` records the inputs that drove this regeneration. `body_hash` records the exact body bytes that vault-lint wrote, so Check 27 can detect manual edits.

    **Conflict detection (Jaccard on definition strings):** for each canonical term appearing in 2+ projects, tokenize each definition (lowercase, strip punctuation `.,;:!?'"()[]{}-`, split on whitespace, drop stopwords `{the, a, an, of, for, in, on, to, and, or, is, are, that, this, with, by, as}`), build a set per definition, compute Jaccard `|A ∩ B| / |A ∪ B|` (empty union = 1.0). For N projects, evaluate all `N*(N-1)/2` pairs; flag the canonical if ANY pair scores `< 0.4`. Emit one line per flagged term: `⚠️ Term '<X>' conflicts across <projectA>, <projectB> (Jaccard <0.NN>): "<defA>" vs. "<defB>" — review whether term needs cross-project disambiguation.`

    **Same-term-same-meaning is NOT a conflict.** If two projects both define "agent" as overlapping ("autonomous LLM worker"), Jaccard ≥ 0.4 and the term passes silently. Aliases-allowed lists are not compared; only canonical-term definitions.

27. **Glossary-master manual edit (tamper detection)** — runs after Check 26 has parsed inputs but BEFORE Check 26 writes the new file.

    **Procedure:**
    1. If `patterns/language-glossary-master.md` does NOT exist: no tamper possible. Skip to write.
    2. If it exists but has no `body_hash` frontmatter field (legacy or hand-created file from before this contract): emit a one-time migration warning and proceed to overwrite:
       ```
       ⚠️ patterns/language-glossary-master.md predates the body_hash contract.
          Overwriting with a fresh derivation. Re-verify any intentional edits
          live in per-project wiki/language.md files.
       ```
    3. If `body_hash` is present: compute sha256 of the existing file's actual body (everything after the frontmatter closing `---` line, excluding the trailing newline). Compare to the recorded `body_hash`.
       - Match → no tamper, proceed to write.
       - Mismatch → flag as critical, then proceed to overwrite per the derived-file contract:
         ```
         ❌ patterns/language-glossary-master.md was hand-edited since the last
            lint run (body_hash mismatch). This file is DERIVED — edits will be
            overwritten. Move your intended change into the per-project
            wiki/language.md instead, then re-run vault-lint.
         ```

## Tier 3: Semantic Checks (opt-in via --semantic)

Tier 3 requires LLM judgment. Token-intensive. Always opt-in.

20. **Contradiction detection** — LLM scans pairs of related (link-neighbor) pages for inconsistent claims. Output: "potential contradiction, review needed" pairs. Never declares a verdict.
21. **Near-duplicate page detection** — LLM compares page summaries + headings. Flag pairs with >80% similarity. Boilerplate-heavy files (status pages, index pages) get false positives — mention this in the report.

Tier 3 produces review candidates only. Never auto-resolves. Never modifies files.

## Hard Rules

1. **Never modify any file.** Report only. No auto-fixes, no auto-deletes, no auto-merges. **Single explicit exception:** Check 26 regenerates `~/Anmols Files/CLAUDE/patterns/language-glossary-master.md` because that file is DERIVED (not authored) by contract. No other writes are permitted, ever.
2. **Tier 3 produces review candidates, not verdicts.** Never declare two pages contradictory. Flag as "potential contradiction, review needed."
3. **Missing disk file = ghost entry removal candidate only.** Never invent missing file content to fill an index gap.
4. **False-positive awareness.** Orphans can be intentional, similar headings can be structural templates, low-word pages can be intentional stubs. All Tier 2 and Tier 3 flags are advisory. Reports must say so.
5. **Tier 2 default scope is changed-files + link-neighborhood, not the full vault.** Full vault Tier 2 only with explicit `--full`.
6. **Tier 3 only with explicit `--semantic` flag.** Never run Tier 3 implicitly. Token cost is high.
7. **No em dashes in any output.** Use commas, periods, or colons.
8. **Skip Tier 2/3 if vault has a `[RESTRUCTURE STUB`]` marker.** Lint requires a finalized vault. Report and stop in that case.
