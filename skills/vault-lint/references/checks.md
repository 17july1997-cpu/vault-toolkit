# vault-lint Check Catalog

21 checks across 3 tiers. Each check has: detection logic, severity, false-positive notes, example output line.

Severity legend: ❌ critical (must fix), ⚠️ warning (review), ✅ pass.

---

## Tier 1: Structural (always run)

### Check 1: Required File Presence

**Detection:** Verify each of the 6 required vault files exists.

```bash
for f in CLAUDE.md wiki/hot.md wiki/index.md wiki/log.md wiki/session-handoff.md wiki/reasoning.md; do
  ls "$f" 2>/dev/null
done
```

`wiki/reasoning.md` is conditional: required only if `.vault-config.yaml` has `reasoning_log: enabled`, OR if the file already exists (legacy vaults).

**Severity:** ❌ critical for any of CLAUDE.md, wiki/hot.md, wiki/index.md missing. ⚠️ warning for log.md, session-handoff.md missing. Conditional for reasoning.md.

**False positives:** none. These are foundational.

**Example:** `❌ Required files: missing wiki/index.md`

---

### Check 2: CLAUDE.md Line Count

**Detection:** `wc -l CLAUDE.md`. Flag if >80 lines.

**Severity:** ❌ critical at >100 lines, ⚠️ warning at 81-100 lines.

**False positives:** none. CLAUDE.md should be routing-only.

**Example:** `❌ CLAUDE.md: 84 lines (limit: 80) — trim needed`

---

### Check 3: Index Drift

**Detection:**
- Parse wiki/index.md for all `[text](path)` entries → set A (files claimed in index)
- `find wiki -maxdepth 2 -name "*.md"` → set B (markdown files actually on disk)
- Ghost entries: A − B
- Unlisted files: B − A, **excluding from the unlisted comparison: the 6 required vault files (hot.md, index.md, log.md, session-handoff.md, reasoning.md), the 2 vault coordination files (`wiki/restructure-manifest.md`, `wiki/vault-index.md`), and anything under `wiki/reasoning_archive/` or `wiki/log_archive/`.** These do not need their own line entries in index.md (manifest/vault-index are referenced under "Vault Coordination" section if at all; archives are referenced under `## Archives` only).

**Severity:** ⚠️ warning.

**False positives:** archived files in index that intentionally point to past locations. Mitigation: archive entries (under `## Archives` section) are checked separately and ghost entries there are advisory only.

**Example:** `⚠️ Index drift: 1 ghost entry (wiki/deleted.md in index, not on disk); 2 unlisted files (wiki/new1.md, wiki/new2.md on disk, not in index)`

---

### Check 4: Invalid Frontmatter Syntax

**Detection:** every wiki/*.md must open with a valid `---` ... `---` YAML block. Parse YAML — flag any that throw parse errors.

Skip files in `wiki/raw/`, `wiki/log_archive/`, `wiki/reasoning_archive/`, `wiki/assets/`.

**Severity:** ❌ critical (malformed YAML breaks routing).

**False positives:** index.md, hot.md, log.md, session-handoff.md may legitimately not start with frontmatter (depending on template). Allowlist these. Also allowlist auto-generated vault coordination files that document themselves in their opening paragraph instead of YAML: `wiki/vault-index.md` (per-page metadata catalog, generated by vault-restructure), `wiki/restructure-manifest.md` (file inventory — does carry minimal YAML for schema_version, but never the full type/title/description set).

**Example:** `❌ Invalid frontmatter: wiki/draft.md — YAML parse error at line 4`

---

### Check 5: Duplicate Page Titles

**Detection:** for every wiki/*.md with valid frontmatter, extract the `title:` field. Group by exact title text. Flag any group with 2+ files.

**Severity:** ⚠️ warning.

**False positives:** intentional aliases (rare). Mitigation: report all duplicates, let user decide.

**Example:** `⚠️ Duplicate titles: wiki/design.md + wiki/design-v2.md both titled "System Design"`

---

### Check 6: Manifest / Vault-Index Hash Drift

**Detection:** if wiki/vault-index.md exists, parse each file's `last_processed` mtime. Compare to current file mtime. Flag files where current mtime > indexed mtime (changed since last vault-restructure).

**Severity:** ⚠️ warning if 1-5 files drifted, ❌ critical if 10+ files drifted.

**False positives:** none — drift means vault-index is stale.

**Example:** `⚠️ Vault-index drift: 3 files modified since last restructure (wiki/arch.md, wiki/design.md, wiki/decisions.md). Run /vault-toolkit:vault-restructure to refresh.`

---

### Check 7: hot.md Staleness

**Detection:** mtime of wiki/hot.md vs max mtime of any KNOWLEDGE wiki/*.md file modified after hot.md.

**Vault meta-file exclusion (apply BEFORE comparison):** the following files are excluded from the comparison because vault-sync writes hot.md mid-flow, before some of them, so they will always look "newer":
- wiki/hot.md (itself)
- wiki/index.md
- wiki/log.md
- wiki/session-handoff.md
- wiki/reasoning.md
- wiki/restructure-manifest.md
- wiki/vault-index.md
- anything under wiki/reasoning_archive/ or wiki/log_archive/

Without this exclusion, every post-Sync vault produces a false-positive hot.md staleness warning because session-handoff.md, reasoning.md, log.md, and index.md are written after hot.md in the Sync flow.

**Severity:** ⚠️ warning if any KNOWLEDGE wiki page is newer than hot.md by more than 24 hours.

**False positives:** mid-session edits. Mitigation: only flag if newer-page age > 24 hours.

**Example:** `⚠️ hot.md staleness: hot.md updated 3 days ago, wiki/arch.md changed 1 hour ago`

---

### Check 8: Broken Internal Links

**Detection:** for every wiki/*.md, parse:
- Markdown links: `[text](path)` — resolve `path` relative to the file's location
- Obsidian wikilinks: `[[page-name]]` — match against any wiki/*.md basename

Skip links inside fenced code blocks (```...```) and inline code (`...`).

External URLs (http://, https://, mailto:) are ignored — vault-lint does not check external availability.

Flag links that resolve to non-existent files.

**Severity:** ❌ critical.

**False positives:** intentional placeholder links (`[TODO](TODO.md)`). Mitigation: report all, user decides.

**Example:** `❌ Broken links: 2 — wiki/index.md → wiki/old-page.md (missing); wiki/design.md → wiki/deleted.md (missing)`

## Tier 2: Quality (default; skip with --fast)

Tier 2 default scope: changed files + link-neighborhood. Full vault Tier 2 only with explicit `--full`.

### Check 9: Orphan Pages

**Detection:** for each wiki/*.md, count inbound links (from any other wiki page). Orphan = 0 inbound links AND not in index.md.

**Severity:** ⚠️ advisory.

**False positives:** intentional quiet pages (drafts, future-reference material). Always advisory. Report should explicitly say "may be intentional."

**Example:** `⚠️ Orphan pages: 2 — wiki/old-notes.md, wiki/draft.md (may be intentional)`

---

### Check 10: Isolated Pages

**Detection:** zero inbound AND zero outbound links. Subset of orphans, more severe.

**Severity:** ⚠️ warning.

**False positives:** standalone reference pages (e.g., a glossary that other pages don't link out of). Mitigation: advisory only.

**Example:** `⚠️ Isolated pages: 1 — wiki/glossary.md (no links in or out)`

---

### Check 11: Oversized Pages

**Detection:** word count of page body, excluding YAML frontmatter and fenced code blocks. Flag if >800 words.

**Severity:** ⚠️ advisory.

**False positives:** legitimately long reference pages (full specifications, intake protocols). Always advisory. Report says "split candidate."

**Example:** `⚠️ Oversized pages: 1 — wiki/full-spec.md (1,240 words). Split candidate.`

---

### Check 12: Stale Frontmatter Dates

**Detection:** `updated:` field in frontmatter. Flag if >90 days old.

**Severity:** ⚠️ advisory.

**False positives:** stable reference pages that don't need updates. Always advisory.

**Example:** `⚠️ Stale frontmatter: 2 pages updated >90 days ago — wiki/principles.md (180 days), wiki/old-decisions.md (210 days)`

---

### Check 13: Duplicate Headings Within a Page

**Detection:** parse all headings (`#`, `##`, `###`, etc.) in a single file. Group by exact text. Flag any group with 2+ matches.

**Severity:** ⚠️ warning.

**False positives:** intentional structural templates (e.g., "Notes" appearing under multiple sections). Mitigation: only flag H1/H2 duplicates by default; H3+ duplicates are advisory.

**Example:** `⚠️ Duplicate headings: wiki/design.md has two H2 sections both titled "Decision"`

---

### Check 14: Missing Required Frontmatter Fields

**Detection:** for every wiki/*.md (excluding archives, raw/, log.md, hot.md, session-handoff.md, reasoning.md, index.md, `wiki/restructure-manifest.md`, `wiki/vault-index.md`), required fields are: `type`, `title`, `description`. Flag any missing. The two auto-generated vault coordination files (restructure-manifest, vault-index) are exempt: they carry only the YAML their generator writes (schema_version, updated, file_total etc.) and document their purpose in their opening paragraph, not in frontmatter.

**Severity:** ⚠️ warning.

**False positives:** none — these fields drive crystallization protocol routing.

**Example:** `⚠️ Missing required fields: 2 — wiki/todo.md (missing: description); wiki/draft.md (missing: type, description)`

---

### Check 15: reasoning.md / log.md Near Thresholds

**Detection:**
- reasoning.md line count vs threshold 400
- log.md line count vs threshold 150

Flag at 80% of threshold (reasoning.md ≥320 lines, log.md ≥120 lines).

**Severity:** ⚠️ advisory.

**False positives:** none. This is a reminder, not a problem.

**Example:** `⚠️ Threshold approaching: reasoning.md at 350/400 lines. Run /vault-toolkit:vault-sync to trigger archival.`

If `reasoning_log: disabled`, skip the reasoning.md threshold check.

---

### Check 16: hot.md / session-handoff.md Contradiction

**Detection:** parse hot.md "Current State" and session-handoff.md "Running State". If both reference the same subject and disagree (e.g., hot.md says "feature X is shipped", session-handoff says "feature X is in progress"): flag.

This is a heuristic check — uses keyword overlap and simple negation detection, not full LLM judgment (Tier 3 territory).

**Severity:** ⚠️ warning.

**False positives:** mid-session state where one file was updated and the other wasn't. Mitigation: flag, let user decide.

**Example:** `⚠️ hot.md / session-handoff contradiction: hot.md says "Auth shipped" but session-handoff Running State says "Auth in progress"`

---

### Check 17: Low-Signal Pages

**Detection:** page has valid frontmatter (with `title:`) but fewer than 50 words of body content (excluding frontmatter and code blocks).

**Severity:** ⚠️ advisory.

**False positives:** intentional brief pages (one-line references, redirect pages). Always advisory.

**Example:** `⚠️ Low-signal pages: 1 — wiki/todo.md (12 words)`

---

### Check 18: Summary Drift

**Detection:** compare `description:` frontmatter field against the page body's first heading text + first paragraph (50 words). Use simple semantic similarity (keyword overlap; no LLM call). Flag if overlap < 30%.

**Severity:** ⚠️ advisory.

**False positives:** descriptions written as routing triggers ("load when X") may not lexically match content. Mitigation: advisory only.

**Example:** `⚠️ Summary drift: wiki/design.md description mentions "auth flow" but body is now about "billing flow"`

---

### Check 19: Dangling Index Sections

**Detection:** parse wiki/index.md sections (## headings). Flag:
- Sections with no entries below
- Entries pointing to non-existent paths (subset of Check 3 ghost entries, but specifically flagged here as "in a section header")

**Severity:** ⚠️ warning.

**False positives:** placeholder sections waiting for first entry. Advisory if section is named like "Future" or "Planned".

**Example:** `⚠️ Dangling index sections: ## Research has no entries; ## Archives lists log_archive/2025.md which doesn't exist`

## Tier 3: Semantic (opt-in via --semantic)

Tier 3 requires LLM judgment. Opt-in only. Tokens: high.

### Check 20: Contradiction Detection

**Detection:** for each pair of pages connected by a link (one hop), use LLM to compare content for inconsistent claims. Output as "potential contradiction" pairs with the conflicting passages.

**Severity:** ⚠️ advisory (review needed).

**False positives:** nuanced distinctions can flatten ("we use X for A, Y for B" misread as "we use X" vs "we use Y"). Mitigation: report includes the specific passages, user decides.

**Hard rule:** never declares contradiction. Always "potential contradiction, review needed."

**Example:** `⚠️ Potential contradiction: wiki/design.md ("we use Postgres") vs wiki/migration.md ("migration completed to MySQL"). Review needed.`

---

### Check 22: Empty-Vault Warning (Tier 2)

**Detection:** count "substantive" knowledge pages in wiki/. EXCLUDE from the count:
- The 6 required vault meta files (CLAUDE.md, hot.md, index.md, log.md, session-handoff.md, reasoning.md)
- The 2 vault coordination files (`wiki/restructure-manifest.md`, `wiki/vault-index.md`)
- Anything under `wiki/reasoning_archive/` or `wiki/log_archive/`
- Files with frontmatter `maturity: placeholder` (seeded topic stubs from Bootstrap)
- Files with frontmatter `type: assets-index` (if such a file exists; the canonical setup does NOT create one but legacy vaults might)
- Files in `raw/` (converted-unreviewed; not yet promoted to wiki/)

A page counts as "substantive" if it has frontmatter `type:` set AND `maturity` other than `placeholder` AND body word count ≥ 50 (excluding frontmatter and code blocks).

**Severity:** ⚠️ warning if 0 substantive pages, advisory if 1-2.

**Recommended actions:**
- If `raw/` has converted-unreviewed files: "Review and promote raw/ files to wiki/ via /vault-toolkit:vault-sync conversation."
- Else if assets/ has 5+ binaries: "Convert binaries via /vault-toolkit:vault-restructure (re-run with conversion accepted)."
- Else: "Start a real work session and run /vault-toolkit:vault-sync to crystallize knowledge into wiki/ pages."

**False positives:** none with the exclusion list applied.

**Example:** `⚠️ Empty vault: 0 substantive knowledge pages. wiki/ has only meta files + 3 placeholder stubs. Action: start a work session and /vault-toolkit:vault-sync, or review raw/ files (5 converted-unreviewed) and promote substantive ones.`

---

### Check 23: Conversion-State Validation (Tier 1)

**Detection:** read `wiki/restructure-manifest.md`. Extract every entry's `Conversion State`. Surface:
- `failed` entries: ❌ critical, listed by path
- `needs-review` entries: ⚠️ warning, listed by path

**Severity:** ❌ critical for `failed`, ⚠️ warning for `needs-review`.

**False positives:** none.

**Example:** `❌ Conversion failed: research/paper-2.pdf (corrupt or unsupported format). Action: re-attempt with /doc-to-markdown or remove from manifest.`

---

### Check 24: Provenance Integrity (Tier 1)

**Detection:** validate provenance from BOTH surfaces:
1. **Markdown frontmatter:** for every wiki/* and raw/* markdown file with `source:` set to `"obsidian-import"` (or any conversion tool), verify the `derivative_of:` path still exists on disk.
2. **Manifest:** for every File Inventory row in `wiki/restructure-manifest.md` with a non-empty `Derivative Of` column, verify the same path exists on disk.

Both checks must agree. Flag any divergence (markdown says one path, manifest says another) AND any broken path on either side.

**Severity:** ⚠️ warning.

**False positives:** intentional asset deletion. Mitigation: if the converted markdown also has a `[USER-PROMOTED]` marker indicating the user explicitly broke the link, skip the warning.

**Example:** `⚠️ Provenance broken: raw/research/paper-1.md derives from assets/research/paper-1.pdf which no longer exists.`

---

### Check 21: Near-Duplicate Page Detection

**Detection:** for each pair of wiki pages, compare summaries + headings using LLM. Flag pairs with >80% similarity.

Skip from comparison: index.md, log.md, session-handoff.md, hot.md, reasoning.md (these have boilerplate structure).

**Severity:** ⚠️ advisory.

**False positives:** boilerplate-heavy pages (status pages, structured templates) report 80%+ similarity even when content differs. Mitigation: exclude known boilerplate, mention this in report.

**Example:** `⚠️ Near-duplicate: wiki/research-q1.md and wiki/research-q1-followup.md share 84% similarity. May be duplicate writing pass.`

## Severity Tally Format

After all checks, summarize:

```
SUMMARY: N critical (❌), N warnings (⚠️), N passed (✅), N advisory
```

Critical (❌) means action is required for vault to function correctly.
Warnings (⚠️) mean review is recommended.
Advisory means likely intentional but worth noting.

---

## Notes for the Skill

- Always end the report with `RECOMMENDED ACTIONS:` — a numbered, prioritized list.
- Never recommend modifications that would alter user content (e.g., never say "delete wiki/old-notes.md"; say "review wiki/old-notes.md or delete if no longer needed").
- If 0 issues found across all run tiers: report `Vault is healthy. No issues detected.` and skip the recommended actions section.
